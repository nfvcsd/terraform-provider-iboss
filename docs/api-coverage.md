## Hosts and authentication

From the collection introduction and request definitions:

| Library | Host | Provider handling |
|---|---|---|
| Authentication | `accounts.ibosscloud.com` (`{{ibossAccounts}}`) | Legacy login only |
| Core | `api.ibosscloud.com` (`{{baseApiDomain}}`) | Fixed default host |
| Gateway | Primary gateway node (`{{gatewayNodeApiDomain}}`) | Discovered, or `gateway_host` |
| Reporting | Primary reporting node | Not used yet |
| Browser Isolation | `api.ibosscloud.com` per the introduction (variable `{{browserIsolationNodeApiDomain}}`) | Not used yet |

Headers sent exactly as documented: `Authorization: Token <token>`,
`User-Agent: ibossAPI`, `Content-Type: application/json;charset=UTF-8` on bodies.
Core policy-group requests also send `Cookie: XSRF-TOKEN=…; JESSIONID=<cloud session>`
and `X-XSRF-TOKEN`; gateway requests send `Cookie: XSRF-TOKEN=…; JESSIONID=<token>`
and `X-XSRF-TOKEN`. (`JESSIONID` is spelled as in the documentation.)

## Implementation decisions

- **Entry identity.** The API has no entry ID; entries are addressed by URL within a group
  (`DELETE … &url=`). Resource ID is `<group_number>/<url>`. Lookup is exact first, then a single
  match ignoring ASCII case and one trailing `/` (the documented examples show both `google.com` and
  `dropbox.com/`). The configured spelling is kept in state; deletes use the server's stored spelling.
- **No update.** No update operation is documented, so every argument forces replacement.
- **No adoption.** Create fails if the URL is already on the list and points to `terraform import`,
  so two configurations (or a manual entry) never silently share ownership of one entry. For the same
  reason `create_before_destroy` cannot be used with these resources.
- **Strict list responses.** Existence and absence are decided only from a list response that contains
  an `entries` array for the requested group and an empty `message`. Anything else is an error, never
  "the entry is gone" (Q9).
- **Confirmation by read-back.** Mutation responses have no documented body, so create and delete
  re-read the list. If the add succeeded but the URL is not on the list afterwards (for example the
  server normalized it), the single new entry is deleted again and the error names the stored spelling.
  If the read-back itself fails, the identity is saved and the resource is tainted.
- **Server-adjusted values.** If iboss stores a configured argument differently (for example trims a
  note), state records the stored value and the apply fails with a list of differences, instead of
  Terraform's "inconsistent result" error. The resource is tainted until the configuration matches.
- **Omitted arguments are omitted on the wire.** The example bodies are not treated as defaults.
- **Serialization.** Mutations of one list/group are serialized within a provider process, because no
  concurrency contract is documented.
- **Retries.** Only GETs are retried (429/502/503/504 and network errors, honouring `Retry-After`,
  max 3 retries). PUT/DELETE, the legacy login request, and HTTP 401 responses are never retried.
  After a legacy-mode 401 the session is discarded; a read is re-run once after a fresh login (only
  when no TOTP code is configured), a mutation is not re-sent.
- **Timed entries** (`isTimedUrl`, `timedUrl`, `timedUrlExpiresInMinutes`) are exposed read-only in
  data sources; resources do not create them because the countdown would cause perpetual drift.
